# Fama deep audit — 2026-08-11

This is the shared engineering record for Codex, Claude, and the maintainer.
It covers the working tree based on `39ba6ae` plus the Dominican-English voice
work already present when the audit began. Update this file rather than
creating a competing handoff note.

## Outcome

No known critical or high-severity dependency vulnerability remains. The
source suite passes 66/66 tests, the extracted core modules have 93.33% line
coverage, every JavaScript file parses, a clean isolated Windows package passes
the release secret gate, and a rendered browser check passes with no console
errors. No real credential pattern was found in the working tree or full Git
patch history.

The audit reviewed all 48 tracked files and the 10 in-scope files added by the
combined Claude/Codex work: 53 text files, 11,789 lines, plus the icon/image
assets. Generated dependencies and existing packaged output were audited via
their manifests, dependency scanner, and a fresh isolated package rather than
treated as first-party source.

## Changes made

### Security and privacy

- Added a strict same-origin Content Security Policy and standard browser
  hardening headers to every local HTTP response.
- Kept the random mutation/spend token same-origin and no-store through
  `/auth.js`; static HTML no longer needs inline token injection.
- Hardened decoded static-path containment, query-string handling, `HEAD`, and
  method rejection. Existing loopback binding, Host allowlist, body limit, and
  mutation-token checks remain required.
- Restricted transcript inline images to PNG/JPEG/GIF/WebP. SVG and unsafe URL
  schemes are discarded. HTTPS image URLs render as explicit links and are
  never fetched automatically.
- Removed the Google Fonts request from the local application. With cloud voice
  disabled, the desktop update check is the only routine outbound app request
  and it contains no transcript content.
- Redacted common API tokens and private keys before cloud narration and from
  client/provider error logs. Removed the spoken-text response header.
- Added 30-second provider timeouts, strict speech kind/speed normalization,
  bounded transcript reads, a bounded partial-line buffer, and a two-megabyte
  backlog byte ceiling.
- Hardened Electron with sandboxing, no renderer Node integration/webviews,
  denied permissions/downloads, HTTPS-only external navigation, IPC sender
  checks, validated project identifiers, safe shortcut creation, and per-user
  config permissions.
- The packaged app now launches its server with Electron's bundled runtime via
  `process.execPath` and `ELECTRON_RUN_AS_NODE=1`, removing the PATH hijack and
  separate-Node prerequisite.
- Broadened package and repository secret exclusions, added Google and
  fine-grained GitHub token scanning, and made the package verifier accept an
  isolated audit directory.

### Reliability, usability, and accessibility

- `Narrator.stop()` now invalidates queued speech, aborts cloud work, settles
  current audio, revokes blob URLs, and cannot replay stale text through local
  fallback.
- Settings now behaves as a labeled modal: focus enters predictably, Tab stays
  inside, Escape closes it, and focus returns to the opener. Status/key/lane
  controls expose appropriate live, expanded, pressed, and label semantics.
- A failed Settings save no longer triggers a misleading voice test.
- Closed a transcript file-descriptor leak and made desktop-shortcut success
  state reflect the actual write result.
- Preserved and tested the pre-existing Dominican-English preset and respectful
  prompt expansion from Claude's working tree.

### Dependencies and delivery

- Pinned Electron `43.3.0`, electron-builder `26.15.3`, electron-packager
  `17.1.2`, and electron-updater `6.8.9`. Both full and production-only
  `npm audit` now report zero vulnerabilities.
- Electron 39 was briefly selected during the shared pass but was already
  end-of-life on 2026-05-05. The final audit uses the supported Electron 43
  line, whose published support window runs through 2027-01-05.
- CI uses deterministic `npm ci`, read-only default permissions, cancellation
  of superseded runs, job timeouts, a high-severity audit gate, and a blocking
  installer build. Node 18 installs production dependencies only; the full
  Electron toolchain runs on Node 22.
- Added weekly Dependabot checks for npm and GitHub Actions.

## Open risks and boundaries

These are not hidden failures and do not block this audit commit:

- Windows artifacts are still unsigned. A code-signing certificate or
  Microsoft Trusted Signing enrollment requires owner identity verification
  and payment; engineering cannot manufacture that trust signal.
- Real macOS/Linux hardware behavior remains unverified. CI currently proves
  Node/server behavior and Windows packaging.
- In-place auto-update is not wired to the distributed installer flow; the app
  detects releases and opens the release page.
- `style-src 'unsafe-inline'` remains because appearance controls set inline
  CSS values. Removing it is a focused styling refactor, not evidence that
  scripts can run inline (`script-src` is strictly self-only).
- Desktop main-process behavior still relies more on package/browser/manual
  checks than unit automation. The highest-value next tests are window/IPC and
  server-lifecycle tests with Electron mocks.
- OpenAI cost figures are explicitly estimates. Provider pricing and model
  availability should be checked against official docs whenever that UI changes.

## Architecture exploration candidates

The audit found real deepening opportunities, but no large refactor was mixed
into the security patch. Choose one before implementation.

1. **Deepen Live Activity Ingest Module**

   **Problem:** provider discovery, session identity, polling, tailer lifecycle,
   normalization, and broadcast orchestration are spread through `server.js`.
   Codex session discovery recursively scans on a timer, while `FileTailer`
   exposes offset/buffer mechanics to orchestration policy.

   **Solution:** create one ingest module that owns provider discovery cadence,
   selected-project matching, tailer lifecycle, and normalized live events.
   Keep Claude/Codex adapters as concrete seams, not a generic filesystem layer.

   **Benefits:** easier provider additions, targeted performance work, and one
   place to prove live-only/no-cross-project semantics.

   **Tests:** provider discovery fixtures, create/rotate/truncate lifecycle,
   project isolation, polling backoff, and normalized event contract tests.

2. **Deepen Selected Projects Module**

   **Problem:** encoded Claude directory names, real working directories,
   labels, and positional environment arrays form one concept but live across
   onboarding, config, Electron, and server startup. A manually browsed real
   path is reduced to an encoded name, and identity is lossy/positional.

   **Solution:** persist a canonical selected-project record with stable ID,
   real path, optional Claude transcript directory, and label; serialize that
   record through one boundary.

   **Benefits:** reliable names, safer migration, simpler Codex matching, and
   fewer parallel arrays that can drift.

   **Tests:** config migration, hyphenated/cross-platform paths, deduplication,
   browse flow preservation, and stable identity after reorder/restart.

3. **Deepen Cloud Narration Module**

   **Problem:** provider calls, rewrite policy, voice-style expansion, cost
   estimates, usage accounting, redaction, and HTTP route handling are spread
   across server/viewer files, with pricing knowledge duplicated.

   **Solution:** give one server-side narration module ownership of validated
   config, rewrite/TTS policy, provider errors, usage estimates, and results.

   **Benefits:** a smaller secret-bearing surface, one source of cost truth,
   and a clean seam for future local or alternate providers.

   **Tests:** no-rewrite threshold, provider timeout/fallback, redaction,
   supported instructions, usage accounting, and model-specific estimates.

4. **Deepen Narrator Module**

   **Problem:** browser narration policy is split between `app.js`,
   `settings.js`, and mutable `Narrator` internals. Cancellation, queue limits,
   provider fallback, and UI state can drift.

   **Solution:** expose a small intent API (`configure`, `enqueue`, `stop`,
   `status`) and keep generation/queue/audio/fallback state private.

   **Benefits:** fewer stale-audio races and direct, deterministic tests of the
   behavior users hear.

   **Tests:** enable/disable transitions, pinned-session policy, queue pressure,
   abort during each phase, fallback once, and state callbacks.

5. **Deepen Desktop Runtime Module**

   **Problem:** `desktop/main.js` is a side-effectful composition root for
   config, migrations, process lifecycle, windows, tray, updates,
   notifications, shortcuts, project selection, and IPC.

   **Solution:** retain a thin composition root and deepen existing concepts
   into desktop config, local-server lifecycle, window policy, and update
   modules. Avoid route-per-file or generic platform abstractions.

   **Benefits:** safer Electron upgrades, mockable lifecycle tests, and clearer
   ownership of security policy.

   **Tests:** server start/stop/error, allowed navigation, IPC sender rejection,
   config migration/permissions, window reuse, and update result handling.

Rejected superficial splits: route-per-file extraction, merging provider
parsers, a generic filesystem interface, centralizing package ignores without
an independent verifier, and splitting tiny leaf modules. Those moves add
indirection without deepening a coherent responsibility.

## Non-negotiable invariants for the next agent

- Keep the server bound to loopback and retain Host plus mutation-token checks.
- Never send transcript content anywhere except the explicitly enabled voice
  provider; never auto-load transcript-supplied remote media.
- Never echo, log, commit, or package a real API key. The artifact scan must be
  a release blocker.
- Preserve provider/session/project attribution and live-only tailing; do not
  replay historical transcripts on startup.
- Preserve the user's existing changes. Check `git status` and the shared audit
  before editing, then update this record with verification evidence.
