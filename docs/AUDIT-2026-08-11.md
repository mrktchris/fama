# Fama v1.0.0 release audit

Audit date: 2026-08-11

This snapshot records what was checked for Fama's first stable public release. It is evidence of a release review, not a formal certification or a substitute for independent penetration testing.

## Published outcome and cross-agent handoff

- PR [#5](https://github.com/mrktchris/fama/pull/5) merged to `master` as commit `51f35de134f042a868d44109e95210451322a750` after all CI, package, and CodeQL checks passed.
- [Fama v1.0.0](https://github.com/mrktchris/fama/releases/tag/v1.0.0) is the sole public release and sole remote tag. Obsolete pre-release entries, assets, tags, and merged remote branches were removed.
- The public installer link and portable link both resolve successfully. Publicly downloaded artifacts matched `SHA256SUMS.txt`:
  - `Fama-Setup.exe`: `f72b2af6d75b6a8f4f3121c1f0651101d2ee3b4a46a341bca50e3d03c20d55ee`
  - `Fama-win32-x64.zip`: `2a530f09e91ef0aa39b4dd9c95c697a7f3b0cd53b328d433e5079800b5fcb9f7`
- `gh attestation verify` succeeded for both downloads. The certificate binds the artifacts to the `v1.0.0` tag, release workflow, GitHub-hosted runner, and merge commit above.
- The published CycloneDX 1.5 SBOM identifies Fama `1.0.0` and 403 components.
- GitHub Pages deployed commit `51f35de`; the live landing page and repository/release pages were visually reviewed after publication.
- Repository metadata now names Claude Code and Codex, unused Projects/Wiki tabs are disabled, merged branches delete automatically, and `master` requires pull requests, conversation resolution, and the complete CI/CodeQL status set. Force-pushes and branch deletion are disabled.
- GitHub secret scanning with push protection, Dependabot alerts/updates, CodeQL, and private vulnerability reporting are enabled; secret, dependency, and code-scanning alert counts were zero at handoff.

Separate uncommitted BUZZ heartbeat-adapter work was present in the shared working tree during publication. It was deliberately preserved and excluded from `v1.0.0`; it needs its own review, tests, changelog entry, PR, and release decision.

## Scope

- Local Node HTTP/SSE server and static-file boundary
- Claude Code and Codex transcript discovery, parsing, and tailing
- Electron desktop lifecycle, navigation, notifications, and updates
- Local and optional OpenAI voice paths
- Viewer rendering, settings, onboarding, and accessibility controls
- Windows installer and portable packaging
- GitHub Actions, release assets, repository security settings, and public documentation

## Evidence collected

- The complete Node test suite passes on the release branch.
- `npm audit --audit-level=high` reports no high- or critical-severity dependency advisory.
- The release workflow rebuilds on a Git tag and reruns tests and the dependency gate before publishing.
- `desktop/verify-package.js` scans unpacked application content for credential patterns and blocks `.env`, usage, PID, log, and key/certificate files.
- Full Git history was searched for common OpenAI, GitHub, AWS, and private-key signatures; no credential-shaped source blob was found.
- GitHub secret scanning and push protection are enabled and report no open alert.
- Dependabot alerts and automated security updates are enabled and report no open alert at audit time.
- GitHub private vulnerability reporting is enabled.
- CodeQL JavaScript analysis runs on pull requests, `master`, and a weekly schedule.
- Release assets include SHA-256 checksums and a CycloneDX SBOM.
- GitHub Actions creates Sigstore-signed build-provenance and SBOM attestations for the installer and portable archive.

## Security properties verified by tests or configuration

- The application server listens on loopback only and rejects spoofed `Host` headers.
- Mutating HTTP routes require a per-process token.
- Browser responses use a restrictive Content Security Policy and other hardening headers.
- The configured OpenAI key is never returned by `/config`.
- Static-file traversal attempts are rejected.
- Transcript image payloads are type-checked and size-bounded; remote URLs are not fetched automatically.
- The updater is limited to packaged builds and requires confirmation before download and before restart/install.
- Desktop navigation permits the local application origin and routes external links through the operating system.

## Distribution status

The Windows x64 installer and portable package are the supported prebuilt artifacts. They are not Authenticode-signed, so SmartScreen may warn on first launch. The project makes no code-signing claim. Users can verify file hashes and GitHub/Sigstore attestations independently from the release page.

## Residual risks and limits

- Agent transcript formats are implementation details of upstream products and may change.
- A loopback application still relies on the security of the local user account and browser/Electron runtime.
- Optional cloud narration intentionally sends the current narration source to OpenAI; it is not a fully offline feature.
- macOS and Linux packaging paths are not claimed as end-to-end supported releases.
- No audit can prove the absence of all vulnerabilities. Report suspected issues privately through GitHub's **Security → Report a vulnerability** flow.
